## 2. 쓴 기술과 알게 된 것

### 2-1. 다른 앱의 메뉴막대 아이콘 읽기 — 손쉬운 사용(Accessibility, AX)
- **방법**: `AXUIElementCreateApplication(pid)` → 속성 `kAXExtrasMenuBarAttribute`(앱의 오른쪽 상태 아이콘 묶음) → `kAXChildrenAttribute`로 아이콘 목록 → 각 아이콘의 `kAXPositionAttribute`·`kAXSizeAttribute`(위치·크기), `kAXTitle/Description/Help`(설명).
- **권한**: 손쉬운 사용. 확인 `AXIsProcessTrusted()`, 설정 열기 URL `x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility`.
- **멈춤 방지**: `AXUIElementSetMessagingTimeout(app, 0.25)` — 응답 없는 앱 하나 때문에 전체가 멈추지 않게. 읽기는 화면 스레드 밖에서.
- **누르기**: `AXUIElementPerformAction(item, kAXPressAction)` → 그 앱의 메뉴가 열림. 앱에 따라 안 먹을 수 있음.
- **안 되는 것**: 옛 방식(창 목록에서 layer 25 창 찾기)은 macOS 27.2에서 하나도 안 잡힘. **다른 앱 아이콘을 옮기거나 지우는 것은 macOS가 허용하지 않음.**
- **좌표 주의**: AX 좌표는 「주 화면 왼쪽 위」가 원점(아래로 갈수록 y 증가), AppKit(NSScreen)은 왼쪽 아래 원점. 변환 함수 `MenuBarItems.axTop(primaryHeight:screenMaxY:)`.

### 2-2. 「가려진 아이콘」 판정 — 세 번 바꾼 끝에 찾은 방법
1. **위치로 판정(실패)**: 노치 범위 안 또는 화면 밖이면 가림 → macOS는 아이콘을 노치 안에 두지 않고 앞 앱 메뉴 글자 쪽으로 보내서 판정 불가.
2. **눌러 보기(hit-test, 실패)**: 시험 프로그램에선 맞았지만, 앱 안에서는 이 앱 자신의 띠·서랍 창이 응답해서 모든 아이콘이 가려짐으로 나옴.
3. **앞 앱 메뉴 끝 위치**: 맨 앞 앱의 `kAXMenuBarAttribute` 자식들 중 가장 오른쪽 끝(`maxX`)보다 왼쪽에 있는 아이콘 = 메뉴 글자에 덮임.
4. **진짜 원인 — 「≪」로 접힌 아이콘**: macOS의 「가려진 메뉴 막대 항목」(MenuBarAgent의 ≪ 단추)으로 접힌 앱은 **AX 목록에서 앱 통째로 사라짐**(읽기 오류 -25212). 그래서 **한 번이라도 읽힌 앱을 번들 ID로 기억**(설정 `menuBarKnown`, JSON)하고, 기억한 앱이 실행 중인데 이번에 안 읽히면 「가려진 것」으로 판정.
   - ≪ 단추 찾기: 번들 ID `com.apple.MenuBarAgent` 앱의 아이콘 중 **가장 왼쪽** 것(추정, macOS 업데이트로 바뀔 수 있음). `kAXPressAction`으로 누르면 펼침↔접힘.
   - 접힌 앱을 열 때: ≪를 눌러 펼치고 최대 3초 기다린 뒤 그 앱 아이콘을 누름. 다시 접기는 자동으로 하지 않음(열린 메뉴가 닫힐 수 있어서).
   - 한계: 처음엔 기억이 비어 있어 사용자가 한 번 ≪로 펼쳐 봐야 함.

### 2-3. 아이콘 그림 찍기 — ScreenCaptureKit
- `SCScreenshotManager.captureImage(in: CGRect)`로 **아이콘 한 칸(메뉴막대 가운데 24pt)만** 찍음. 화면 전체는 찍지 않음.
- **권한**: 화면 기록. 확인 `CGPreflightScreenCaptureAccess()`(묻지 않음), 요청 `CGRequestScreenCaptureAccess()`(처음 한 번만 macOS가 물음), 설정 URL `…?Privacy_ScreenCapture`.
- 그림은 **메모리에만**(파일·UserDefaults 저장 안 함, 로그에도 안 남김). 노치 화면에서 찍은 그림 우선, 60초 지나면 다시 찍음, 다크/라이트 바뀌면 버림. 못 찍으면 앱 아이콘(`NSWorkspace`)으로 대신.
- 1단계 시험: 개발판에 「찍어 보기」 단추를 잠깐 넣어 노치 화면에서 15/15 성공 확인 후 시험 코드 삭제 — **처음 쓰는 기술은 작은 시험부터** 원칙이 잘 맞았던 사례.

### 2-4. 노치 아래 막대 창 — NSPanel
- `NSPanel(styleMask: [.borderless, .nonactivatingPanel])` — 눌러도 이 앱이 앞으로 오지 않음(다른 앱 메뉴를 열어야 하니까).
- `level = .statusBar`, `collectionBehavior = [.canJoinAllSpaces, .stationary, .ignoresCycle]`.
- **전체 화면 앱에서 숨기기**: `.fullScreenAuxiliary`를 **넣지 않으면** 전체 화면 위에 나타나지 않음(별도 감지 코드 불필요).
- 갱신: 10초 타이머(여유 2초) + `NSWorkspace` 알림(앱 실행·종료, 데스크톱 전환) 1초 뒤.
- 배경: 찍힌 그림의 배경이 메뉴막대 색이라 유리(Liquid Glass) 대신 띠 색 단색이 더 자연스러웠음.
- 한계: 최대화한 창의 제목줄 가운데를 가릴 수 있음.

### 2-5. 개발판 분리 (v0.10.1) — 1.0에서도 다시 쓸 만한 것
- `project.yml`에서 Debug만 번들 ID `local.toptiroir.app.dev`, 이름 「TopTiroir Dev」, 실행 파일 `TopTiroirDev`.
- 설정(UserDefaults)·권한·로그인 항목은 번들 ID별이라 자동 분리. 저장 폴더는 코드(`AppIdentity.supportFolderName`)로 `TopTiroir-Dev`.
- ad-hoc 서명이라 개발판은 빌드마다 권한(손쉬운 사용·화면 기록)이 풀릴 수 있음.
